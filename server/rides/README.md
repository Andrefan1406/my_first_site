# Система служебного транспорта (заявки на поездки)

Аналог агрегатора такси для служебных легковых поездок компании. Сотрудник
подаёт заявку → она сразу попадает в общий пул → свободные водители видят
её одновременно и берут первым нажатием («Взять заказ») → диспетчер только
наблюдает и вмешивается вручную лишь как исключение (принудительное
назначение / отмена).

Роли: `employee` (заказчик), `dispatcher`, `driver`, `admin` (админ именно
этого модуля — CRUD водителей/машин и назначение ролей, отдельно от общего
`/admin` сайта).

## Стек

- Backend: Node.js + Express, роутеры в `server/rides/`
- БД: SQLite (`better-sqlite3`), файл `server/rides/data/db.sqlite`
  (создаётся автоматически, в git не попадает — см. `.gitignore`)
- Реалтайм: Socket.io (комнаты `drivers`, `dispatcher`, `employee:{id}`, `driver:{id}`)
- Аутентификация: тот же Firebase Auth, что и у остального сайта — своего
  JWT/паролей нет. Валидного логина недостаточно для доступа: нужна ещё и
  запись в таблице `users` этого модуля с ролью (её создаёт admin на
  странице `/rides-admin`)

## Запуск

Из корня проекта (там же, где обычный `npm install`/`npm start` для
остального сайта):

```bash
npm install
```

Два процесса, в двух терминалах (как и весь остальной сайт — единого
`npm run dev` в проекте нет):

```bash
npm run server   # backend, включая /api/v1/* и Socket.io — http://localhost:4000
npm start        # frontend — http://localhost:3000
```

## Тестовые данные

```bash
npm run rides:seed
```

Добавит 2 водителей, 2 машины, 2 сотрудника, диспетчера, админа модуля и
2 тестовые заявки в пуле. **Важно:** email в сиде — вымышленные. Чтобы
реально войти под одним из них, под тем же email должен существовать
аккаунт в Firebase Authentication проекта — сид этого не делает, он только
заполняет SQLite.

Завести сами аккаунты в Firebase Authentication (email/пароль из
`create-test-users.js`, совпадают с email из сида) можно одной командой —
нужен service account ключ именно проекта `my-first-site-16a0c`
(Firebase Console → Project Settings → Service accounts → Generate new
private key; НЕ коммитить в git):

```bash
GOOGLE_APPLICATION_CREDENTIALS=./путь/к/ключу.json npm run rides:create-test-users
```

Тот же ключ нужен и для работы страницы `/rides-admin` в целом: вкладка
«Пользователи и роли» вызывает `GET /api/v1/users`, а он читает список
пользователей Firebase через `listUsers()` — эта операция, в отличие от
проверки токена (`verifyIdToken`, ей хватает одного `projectId`, см.
`server/rides/auth.js`), требует полноценных credentials. Поэтому на
проде/локально задайте `GOOGLE_APPLICATION_CREDENTIALS` и для самого
backend-процесса (`npm run server`), не только для разового скрипта.

## Как назначить себе роль (первый запуск)

Раздел `/rides-admin` сам требует роль `admin`, поэтому самому первому
админу роль нужно выдать в обход UI, напрямую в БД (дальше уже можно
управлять ролями через страницу):

```bash
node -e "
const { initSchema, getWriteDb } = require('./server/rides/db');
initSchema();
getWriteDb()
  .prepare(\`INSERT INTO users (email, name, phone, role, full_site_access)
             VALUES (?, ?, ?, 'admin', 1)
             ON CONFLICT(email) DO UPDATE SET role='admin', full_site_access=1\`)
  .run('ваш-email@example.com', 'Ваше имя', '+7...');
"
```

Дальше зайдите на сайт под этим email и откройте `/rides-admin` — там уже
можно назначать роли всем остальным пользователям сайта (чекбокс/выпадающий
список на вкладке «Пользователи и роли»).

## Настройки

- `RIDE_STALE_THRESHOLD_MINUTES` — через сколько минут заявка без водителя
  подсвечивается диспетчеру как «зависшая» (по умолчанию 15).
- `RIDES_DATA_DIR` — путь к SQLite-файлу, если нужно переопределить (на
  хостинге без примонтированного диска БД стирается при каждом деплое —
  тот же приём, что и у `CONCRETE_DATA_DIR` в остальном проекте).

## Дальнейшее развитие (не реализовано, заложено как точки расширения)

- 2ГИС API — построение маршрутов/расчёт расстояния по `from_address`/`to_address`.
- Telegram Bot API — дублирование уведомлений (новый заказ в пуле, заказ взят) туда же, куда сейчас идёт Socket.io.

Ни то, ни другое не требуется для работы системы — оба пункта опциональны и
не имеют заглушек в коде, чтобы не тащить недоделанную интеграцию.
